# 系統參數

在畫面上調整**系統名稱、各種紀錄的保留天數、監控與告警的門檻、流量與忘記密碼的限制、密碼規則與登入鎖定、兩步驟驗證、AI 用量上限與備份**，按儲存後**立即生效，不需要重新啟動網站**。沒有改過的參數沿用伺服器設定檔的值，隨時可以「還原為設定檔值」。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：以前要改保留天數或系統名稱，得請部署人員改伺服器的設定檔（系統名稱還要重新啟動）；現在管理員在這一頁就能改，而且每一次修改都留下稽核紀錄。
- **誰會用到**：負責維運的系統管理員。上線時設定系統名稱與保留天數；之後依法規、磁碟空間或告警頻率調整。
- **它在系統的哪個位置**：左側選單「系統管理 › 系統設定與維運 › 系統參數」。改了保留天數之後，清除的動作由「排程作業」頁的各個清理作業執行。
- **開始前要準備**：知道各種紀錄依規定要保留多久（例如稽核紀錄是否有保存年限）、希望多久收到一次例外告警。
- **做完會得到**：新的值馬上生效（各參數的「生效」說明寫了確切時機）；表格的「來源」欄會顯示「系統參數」；稽核紀錄多一筆 `SystemParameter.Update`。
- **它不做什麼**：不能改任何人的密碼（只能設定密碼的規則），也不能改金鑰、連線字串、檔案路徑、版本號與排程的執行時間（這些仍在伺服器設定檔）；不能在這裡設定告警的收件人；不會立刻刪除資料（保留天數改短後，由下一次排程清理執行）。

## 一、功能摘要

在這裡可以做什麼：

- 依「系統識別」「資料保留」「監控與告警」「安全與流量」「密碼與登入」「AI 用量」「備份」七類，看每個參數的目前值、設定檔的值、來源與說明。
- 按「修改」輸入新值並儲存，立即生效。
- 按「還原為設定檔值」取消自己的修改，回到伺服器設定檔的值。
- 縮短保留天數時，系統會先跳出紅色的確認窗提醒你資料會被永久刪除。
- 每一次修改與還原都會寫進稽核紀錄（舊值 → 新值）。

## 二、這個頁面在做什麼

### 誰會使用、為什麼要用

| 角色 | 為什麼要用 |
|---|---|
| 系統管理員（上線設定） | 設定系統名稱與簡介，讓登入頁、側邊欄、PDF 報告與系統寄出的信件顯示正確的名稱。 |
| 系統管理員（依規定調整） | 稽核紀錄有保存年限規定時，把保留天數調長或設為 0（不清除）。 |
| 系統管理員（處理問題） | 磁碟吃緊時縮短保留天數；告警信太多或太少時調整告警門檻；被誤判為大量請求時調整流量上限。 |

### 值從哪裡來

- 每個參數都有一個**設定檔的值**（伺服器的設定檔，由部署人員維護）。
- 你在這一頁修改後，改用**系統參數**的值，蓋過設定檔的值；按「還原為設定檔值」就回到設定檔的值。
- 你改過的值存在系統的資料庫裡，網站重新啟動、或有多台主機時都會套用（其他主機約 1 分鐘內同步）。
- 系統更新後若某個值已經不在允許範圍內，它會標示「未套用」並暫時沿用設定檔的值，請重新修改或還原。
- **系統第一次啟動時不會把設定檔的值寫進資料庫**。資料庫只存你在這一頁改過的參數；沒改過的（來源顯示「設定檔」）一律即時讀設定檔，部署人員改了設定檔就會生效，不必到這一頁再改一次。
- **改過的參數，設定檔或環境變數再怎麼改都不會生效**，直到你按「還原為設定檔值」。部署人員回報「改了設定檔卻沒效果」時，先看這一頁那個參數的來源是不是「系統參數」。
- **系統更新後新增的設定也不會寫進資料庫**。開放在這一頁修改的新參數會直接出現在表格裡，來源顯示「設定檔」；沒開放的就只在設定檔裡。

### 哪些設定只能改伺服器設定檔

這一頁只放「不是機密、網站執行中改了就能套用、單一個值」的參數。下面這些不在這一頁，請部署人員修改伺服器的設定檔（`appsettings.json`、`appsettings.Production.json`）或環境變數。「改了之後」指設定檔存檔後多久生效。

| 設定檔區段 | 管什麼 | 改了之後 |
|---|---|---|
| `SystemSettings:ConnectionStrings` | 資料庫連線 | 重新啟動網站後 |
| `SystemSettings:ExternalFileSystem` | 資料庫、附件、例外堆疊、Token 原始檔、AI 對話內容、金鑰、備份、上傳與下載等目錄 | 重新啟動網站後 |
| `SystemSettings:SystemInformation:SystemVersion` | 系統版本號（每次發行由開發人員更新） | 重新啟動網站後 |
| `SystemSettings:Upload` | 允許上傳的副檔名 | 重新啟動網站後 |
| `NLog:BasePath` | 日誌檔放在哪裡 | 重新啟動網站後 |
| `JwtSettings` | Web API 的登入權杖（簽章金鑰、有效時間） | 重新啟動網站後 |
| `CookieSettings` | 登入狀態保留多久、「記住我」天數 | 重新啟動網站後 |
| `GoogleOAuthSettings` | Google 登入的開關、用戶端憑證與預設角色 | 重新啟動網站後 |
| `BootstrapSettings` | 內建管理員 support 的帳號、姓名、Email 與密碼 | 重新啟動網站後；⚠️ 每次啟動都會把 support 的密碼改成設定檔的值，姓名與 Email 只在第一次建立帳號時使用 |
| `EmailSettings` | 寄信主機、帳號密碼、寄件人、信件連結的網址 | 寄信立即使用新值；登入與忘記密碼頁面的部分顯示要重新啟動網站，建議改完重新啟動 |
| `AiSettings` | AI 服務的位址、金鑰、模型與逾時 | 下一次 AI 呼叫起 |
| `AiPricingSettings` | AI 模型的單價與匯率 | 之後記錄的費用（已記錄的不會重算） |
| `ExceptionAlertSettings:Recipients` | 例外告警信的收件人（同一區段的四個門檻在這一頁） | 下一封告警信起 |
| `ScheduledJobSettings:Enabled`、`ScheduledJobSettings:Jobs` | 排程總開關、各作業的執行時間（執行紀錄保留天數在這一頁；各作業的啟用／停用在「排程作業」頁） | 立即，從現在重新排定下一次執行 |
| `CacheSettings` | 快取方式與 Redis 連線 | 重新啟動網站後 |
| `Cors` | 允許哪些網站跨網域呼叫 Web API | 重新啟動網站後 |
| `AllowedHosts`、`ForwardedHeaders` | 允許的主機名稱、信任的反向代理 | 重新啟動網站後 |
| `Swagger`、`Security` | 正式環境是否開放 API 文件、錯誤回應是否附上例外細節 | 重新啟動網站後 |
| `AutoMapper:LicenseKey` | 元件授權碼 | 重新啟動網站後 |
| `Logging:LogLevel` | 沒有作用（日誌等級由 `nlog.config` 決定，執行中可在「日誌等級設定」頁暫時調整，重新啟動網站後還原） | — |

### 需要的權限

| 權限 | 可以做的事 |

## 四、建議這樣操作，會得到什麼

### 上線時設定系統名稱

1. 在「系統識別」的「系統名稱」按「修改」，輸入正式名稱後儲存。
2. 需要的話也修改「系統簡介」。
3. 換一個頁面或重新整理，側邊欄與「關於」就會顯示新的名稱。

**會得到什麼**：登入頁、側邊欄、瀏覽器分頁、PDF 報告與系統寄出的信件都使用新的名稱，不必請部署人員改設定檔或重新啟動網站。

### 依規定延長稽核紀錄的保存期間

1. 在「資料保留」的「稽核紀錄保留天數」按「修改」。
2. 輸入規定的天數（例如 1825，約 5 年），或輸入 0 表示永遠不自動清除。
3. 儲存。

**會得到什麼**：之後的排程清理只會刪除超過新天數的紀錄；稽核紀錄裡也留下一筆 `SystemParameter.Update`，記錄是誰在何時把天數從多少改成多少。

### 公司要求更嚴格的密碼

1. 在「密碼與登入」把「密碼最少字元數」改成 12，並把「密碼須含大寫字母」「密碼須含符號」改成「開啟」。
2. 需要定期換密碼時，把「密碼有效天數」設成例如 90。

**會得到什麼**：之後任何人設定密碼（新增使用者、改密碼、忘記密碼重設）都要符合新規則；現有的密碼不會因此失效。
設了有效天數之後，密碼超過天數的人登入時會被帶去換密碼，到期前 7 天內會在鈴鐺收到提醒（每天早上 8 點檢查，同一個到期日只提醒一次）。

### 要求所有管理員使用兩步驟驗證

1. 先確認你自己已經在「個人資料」→「兩步驟驗證」開啟了（不然存檔後你也會被帶去設定）。
2. 在「密碼與登入」把「管理員必須使用兩步驟驗證」改成「開啟」。
3. 不希望有人勾「記住這台裝置」時，把「記住裝置天數」改成 0。

**會得到什麼**：還沒設定的管理員下一次切換頁面時被帶到「兩步驟驗證」頁，設定完成前不能使用其他頁面；support 帳號不受影響，可以在大家都卡住時當救援入口。

### 控制 AI 的花費

1. 先到「Token 用量」看最近每天、每月大約花多少，以及有沒有「未定價」的提示（未定價的呼叫以 0 元計，上限管不到）。
2. 在「AI 用量」設定「全系統每月上限」（例如 3000）與「每人每日上限」（例如 100）。

**會得到什麼**：用到 80% 時鈴鐺會收到通知（每人上限通知本人，全系統上限通知所有管理員）；達到上限後 AI 分析會暫停並顯示何時重置，全系統達上限時管理員另外收到信。需要臨時放寬時把上限調高或改成 0，立即生效。

### 磁碟空間吃緊，想縮短保留天數

1. 先到相關頁面匯出要留存的資料（例如稽核紀錄的 CSV）。
2. 在這一頁把保留天數改短，在紅色確認窗按「確定縮短」。
3. 想馬上清掉，再到「排程作業」對應的清理作業按「立即執行」。

**會得到什麼**：超過新天數的舊資料被永久刪除，磁碟空間釋放；不按「立即執行」的話，會在下一次排程（預設每天 03:00）刪除。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **設定檔的值** | 伺服器設定檔裡的值，由部署人員維護。這一頁沒改過的參數都用它。 |
| **系統參數** | 在這一頁改過的值，存在資料庫裡，會蓋過設定檔的值。 |
| **未套用** | 資料庫裡有改過的值，但它已經不合法（例如系統更新後範圍變了），所以暫時沿用設定檔的值。 |
| **保留天數** | 紀錄保留多久，超過的會由排程作業自動刪除；0 通常表示不自動刪除（各參數的範圍欄有寫）。 |
| **立即生效** | 存檔後不需要重新啟動網站；確切時機見每個參數的「生效」說明（例如保留天數是在下一次排程清理時使用）。 |

## 七、常見問題

**問：改了系統名稱，側邊欄為什麼還是舊的？**
答：已經開著的畫面要換一個頁面或重新整理才會更新；新寄出的信件與新產生的 PDF 會立刻使用新名稱。

**問：保留天數改短了，資料為什麼還沒被刪？**
答：刪除由排程作業執行（預設每天 03:00）。想馬上刪，請到「排程作業」對該清理作業按「立即執行」。

**問：部署人員改了設定檔，為什麼這裡的「目前值」沒變？**
答：這個參數在這一頁被改過，系統參數會蓋過設定檔的值。要改用設定檔的值，請按「還原為設定檔值」。

**問：為什麼找不到密碼、金鑰或告警收件人？**
答：機密資料、檔案路徑、版本號、排程執行時間與告警收件人這類值刻意不放在畫面上，仍由部署人員在伺服器設定檔維護。完整清單見第二段「哪些設定只能改伺服器設定檔」。

**問：系統第一次啟動時，設定檔的值會被寫進資料庫嗎？**
答：不會。資料庫只存你在這一頁改過的參數，其他參數每次都直接讀設定檔。所以沒改過的參數，部署人員改設定檔就會生效；改過的參數則以這一頁為準。

**問：系統更新後多了新的設定，會自動出現在這裡嗎？**
答：只有開放在這一頁修改的參數會出現，來源顯示「設定檔」，值取自設定檔；不會寫進資料庫，也不需要你做任何事。沒開放的新設定只在設定檔裡，由部署人員維護。

**問：鈴鐺裡的通知會留多久？**
答：看「資料保留」的兩個參數。「已讀站內通知保留天數」（預設 7 天）從標為已讀那一刻起算，到期就刪除；「站內通知保留天數」（預設 90 天）從通知建立時起算，不論已讀未讀都刪除，所以沒讀的通知最多留 90 天。兩者都由排程作業「站內通知清理」在下一次執行時（預設每天 03:00）刪除；把「已讀站內通知保留天數」設為 0，已讀的就不提早刪除。使用者也可以在鈴鐺裡自己刪除單則或「清除已讀」。

**問：還是解決不了怎麼辦？**
答：請記下發生時間、要修改的參數與輸入的值、畫面或窗內的訊息（最好截圖），以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
