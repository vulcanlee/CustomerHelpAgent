# 資料庫用量

查看資料庫**實際佔了多少磁碟空間**、有多少空間**可以回收**，以及**每一張資料表**的紀錄筆數、資料量估算與索引數。這一頁只能看，沒有任何會改動資料的按鈕。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：主機磁碟吃緊、備份檔越來越大，或刪了很多資料檔案卻沒變小時，用這一頁確認資料庫到底佔了多少、哪張表最大。
- **誰會用到**：負責主機容量與備份規劃的系統管理員；定期巡檢時也可以順手記下各表筆數，觀察成長速度。
- **它在系統的哪個位置**：左側選單「系統管理 › 監控與診斷 › 資料庫用量」；和「Token 用量」一起負責看容量與費用，不負責找錯誤。
- **開始前要準備**：不需要準備任何條件，打開頁面就會自動讀取；閱讀前先記得同一頁上有四種意思不同的「大小」。
- **做完會得到**：六張容量卡片（磁碟占用、三個檔案各自的大小、已配置、可回收），以及一張列出每張資料表筆數、資料量估算與索引數的清單。
- **它不做什麼**：不能刪資料、不能壓縮或整理資料庫，也不會自動更新；要看最新數字請重新整理瀏覽器頁面。

## 一、功能摘要

在這裡可以做什麼：

- 看資料庫在硬碟上實際吃掉多少空間（「磁碟占用總計」），以及主檔、預寫日誌、共享記憶體索引三個檔案各自的大小。
- 看資料庫內部已配置多少空間、其中有多少是刪除資料後留下、可以回收的閒置空間。
- 看每一張資料表有幾筆資料、欄位內容大約多少位元組、建了幾個索引。
- 點資料表清單的欄位標題排序，找出筆數最多或內容最大的資料表。

本系統使用單一檔案型的資料庫，所以卡片上的「檔案大小」就是它在硬碟上實際佔用的空間。頁面在打開時讀取一次，之後不會自己更新。

## 二、這個頁面在做什麼

### 誰會使用、為什麼要用

| 角色 | 為什麼要用 |
|---|---|
| 系統管理員（主機維護） | 評估磁碟是否足夠、是否要安排整理資料庫或擴充磁碟。 |
| 系統管理員（日常巡檢） | 定期記下各表筆數，看出哪些紀錄（例如稽核紀錄、Token 用量）成長最快、需要清理。 |

### 四種「大小」不能混用

這一頁最重要的觀念是：**同一頁上有四種不同的「大小」，不能互相加減比較**。

| 哪一種大小 | 在畫面的哪裡 | 回答的問題 |
|---|---|---|
| 檔案大小 | 磁碟占用總計、主資料庫檔、預寫日誌、共享記憶體索引 | 硬碟實際被吃掉多少？ |
| 已配置 | 「已配置」卡片 | 資料庫內部總共開了多少頁的空間？ |
| 可回收 | 「可回收」卡片 | 其中有多少是閒置、整理後可以還給作業系統的？ |
| 資料量估算 | 資料表清單的「資料量估算」欄 | 每張表的欄位內容大約有多少位元組？ |

要回答「硬碟被吃掉多少」，只看「磁碟占用總計」。資料表清單的資料量估算加起來，**不會等於**上面任何一張卡片的數字。

### 為什麼刪了資料檔案卻沒變小

刪除資料時，資料庫只會把那些空間標成「閒置」，留給之後的新資料使用，檔案本身不會自動縮小。這些閒置空間會算在「可回收」卡片裡。要真正把檔案縮小，需要另外整理資料庫（VACUUM），這一頁沒有提供這個動作，請洽負責伺服器維護的人員安排。

### 需要的權限

| 權限 | 可以做的事 |
|---|---|
| 管理員（使用者管理裡勾選了「管理員」） | 左側選單看得到這一頁，可以進入查看全部內容。 |
| 其他使用者 | 選單不會出現這一頁；直接輸入網址會看到「你沒有權限存取此頁面」。這一頁無法透過角色管理授權給一般角色。 |

### 它跟其他頁面的分工

| 你想做的事 | 該去哪 |
|---|---|
| 看資料庫佔多少空間、哪張表最大 | 這一頁 |
| 看主機磁碟還剩多少、資料庫能不能連線 | 「系統健康監控」 |
| 清除過舊的 AI 用量紀錄 | 「Token 用量」 |
| 清除過舊的稽核紀錄 | 「稽核紀錄」 |
| 清除長期未再發生的例外紀錄 | 「系統例外紀錄」 |

## 三、畫面上有哪些按鈕、各自做什麼

這一頁**沒有任何按鈕**，所有內容在打開頁面時讀取一次；讀取中會顯示「正在讀取資料庫用量...」。要更新數字，請重新整理瀏覽器頁面。

### 容量卡片（上方六張）

| 欄位 | 意思 | 範例 | 怎麼填或怎麼用 |
|---|---|---|---|
| 磁碟占用總計 | 主檔、預寫日誌、共享記憶體索引三個檔案的大小加總，卡片下方註明「主檔 + WAL + SHM 三個檔案」。 | 48.6 MB | 唯一能回答「硬碟被吃掉多少」的數字。 |
| 主資料庫檔 | 資料庫主檔本身的大小，下方顯示檔名。 | 45.2 MB（`BackendDB.db`） | 只看得到，不能操作。 |
| 預寫日誌 | 尚未併回主檔的交易紀錄檔。檔案不存在時下方顯示「目前無此檔案（已 checkpoint）」。 | 3.4 MB（`BackendDB.db-wal`） | 暫時偏大是正常的，資料庫會在適當時機併回主檔並縮小它。 |
| 共享記憶體索引 | 資料庫運作時使用的輔助小檔案。檔案不存在時下方顯示「目前無此檔案」。 | 32 KB | 通常很小，不需要特別注意。 |
| 已配置 | 資料庫內部的頁數乘以每頁大小，下方寫「N 頁 × N B，含尚未併回主檔的頁」。 | 12,000 頁 × 4,096 B | 因為包含還在預寫日誌裡的頁，可能比主資料庫檔還大。 |
| 可回收 | 刪除資料後留下的閒置頁，下方寫「N 個閒置頁，VACUUM 可釋放」。 | 1,500 個閒置頁 | 數字越大，代表整理資料庫後能釋放越多空間。 |

卡片下方有一段固定說明：「預寫日誌（WAL）比主檔大是正常的」，它是還沒併回主檔的交易紀錄，不代表資料量暴漲。

再下面還有一段說明：「資料量估算」不是磁碟占用量，它是各欄位內容的位元組加總，**不含索引、頁面碎片與已配置的閒置頁**，與實際磁碟占用會有差距。因為系統使用的資料庫版本沒有提供逐表統計實際頁數的功能，只能用欄位內容的長度估算。

### 資料表清單

| 欄位 | 意思 | 範例 | 怎麼填或怎麼用 |
|---|---|---|---|
| 資料表 | 資料表名稱。系統內部使用的表（例如記錄資料庫版本的表）也會列出，因為它們同樣佔空間。 | `AuditLog` | 預設依名稱由 A 到 Z 排序，點欄位標題可切換排序。 |
| 紀錄筆數 | 這張表目前有幾筆資料。讀不到時顯示「—」。 | 12,345 | 可排序；由大到小排就能找出筆數最多的表。 |
| 資料量估算 | 欄位內容的位元組加總，不是磁碟用量。估算失敗時顯示「—」，滑鼠移上去可看失敗原因。 | 1.5 MB | 可排序，依實際數值排序（不會把 1.5 MB 排在 900 KB 後面）。只適合各表互相比較。 |
| 索引數 | 這張表建了幾個索引（含唯一值限制自動產生的索引）。 | 3 | 可排序。索引也佔空間，但沒有算進資料量估算。 |

> 清單一次列出全部資料表，不分頁。

## 四、建議這樣操作，會得到什麼

### 主機磁碟快滿了，想知道資料庫佔多少

1. 打開這一頁，看「磁碟占用總計」。
2. 看「預寫日誌」是否特別大；暫時偏大是正常的，過一段時間通常會縮回去。
3. 看「可回收」，估計整理資料庫後能釋放多少空間。

**會得到什麼**：資料庫在硬碟上的實際用量，以及其中有多少是可以回收的閒置空間，作為是否安排整理資料庫或擴充磁碟的依據。

### 找出成長最快的資料表

1. 點「紀錄筆數」欄位標題，改成由大到小排序。
2. 再點「資料量估算」欄位標題，看哪張表的內容最大。
3. 記下前幾名的數字，下個月再來比對一次。

**會得到什麼**：各表的相對大小與成長趨勢，知道該優先清理哪一類紀錄。

> 王小明每月初巡檢時打開「資料庫用量」，發現 `AuditLog` 的筆數比上個月多了一倍。他到「稽核紀錄」先匯出一年前的紀錄備份，再清除 365 天前的紀錄；回到這一頁重新整理後，筆數下降了，「可回收」也跟著增加。

### 清除大量舊紀錄後，確認空間是否釋放

1. 在「Token 用量」「稽核紀錄」或「系統例外紀錄」清除舊資料後，重新整理這一頁。
2. 看對應資料表的「紀錄筆數」是否下降。
3. 看「可回收」是否增加；「磁碟占用總計」通常不會立刻變小。

**會得到什麼**：確認資料確實已刪除，並了解要真正縮小檔案，還需要另外整理資料庫。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **磁碟占用總計** | 資料庫三個檔案在硬碟上的實際大小加總，是唯一能回答「硬碟被吃掉多少」的數字。 |
| **預寫日誌（WAL）** | 新寫入的資料先記在這個檔案，之後再併回主檔；暫時比主檔大是正常的。 |
| **checkpoint** | 把預寫日誌的內容併回主檔的動作，由資料庫自動進行。 |
| **共享記憶體索引（SHM）** | 資料庫運作時使用的輔助小檔案。 |
| **頁** | 資料庫內部配置空間的單位，每頁大小固定。 |
| **已配置** | 資料庫內部總頁數乘以每頁大小，包含還在預寫日誌裡的頁。 |
| **可回收** | 刪除資料後留下的閒置頁，整理資料庫後可以還給作業系統。 |
| **VACUUM** | 整理資料庫、把閒置頁還給作業系統的維護作業；這一頁不提供這個動作。 |
| **資料量估算** | 各欄位內容的位元組加總，不含索引、碎片與閒置頁，只適合各表之間互相比較。 |
| **索引** | 讓查詢變快的輔助資料，同樣佔空間，但不算在資料量估算裡。 |

## 七、常見問題

**問：我刪了很多資料，為什麼磁碟占用總計沒有變小？**
答：刪除只會把空間標成閒置，留給之後的新資料使用，檔案本身不會自動縮小。這些閒置空間會顯示在「可回收」卡片。要真正縮小檔案，需要由負責伺服器維護的人員整理資料庫。

**問：為什麼資料表清單的資料量估算加起來，和磁碟占用總計差很多？**
答：兩者本來就是不同的東西。資料量估算只算欄位內容本身，不含索引、頁面碎片與閒置頁；磁碟占用總計是檔案的實際大小。四種大小不能互相加減比對。

**問：預寫日誌比主資料庫檔還大，是不是出問題了？**
答：通常不是。預寫日誌是還沒併回主檔的交易紀錄，資料庫會在適當時機併回並縮小它。若它長時間持續變大、完全不縮回，才需要請負責伺服器的人員檢查。

**問：數字會自動更新嗎？**
答：不會。這一頁只在打開時讀取一次，要看最新數字請重新整理瀏覽器頁面。

**問：清單裡有些看不懂的資料表名稱，可以刪掉嗎？**
答：不行，這一頁也沒有刪除功能。那些是系統運作需要的內部資料表（例如記錄資料庫版本的表），它們同樣佔空間，所以一併列出供參考。

**問：還是解決不了怎麼辦？**
答：請記下發生時間、操作的頁面與按鈕、畫面或右下角的訊息（最好截圖；右下角的錯誤訊息可按「複製」，內容、時間與錯誤追蹤碼會一起放進剪貼簿），以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
