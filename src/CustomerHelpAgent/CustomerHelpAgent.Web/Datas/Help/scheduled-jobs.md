# 排程作業

系統在**固定時間自動做的事**（例如每天清除過期的紀錄）都列在這一頁：可以看到**下次什麼時候跑、上次跑得順不順利**，需要時**立即執行**一次，或暫時**停用**某個作業。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：系統每天會在背景自動清除過期的稽核紀錄、例外紀錄、AI 對話紀錄、Token 用量紀錄與站內通知，並把刪除超過保留天數的專案、分類、團隊、使用者與角色永久刪除，每天凌晨 2 點另外做一次系統備份，早上 8 點提醒密碼快到期的人（有設定密碼有效天數時）；這一頁讓你確認它們真的有跑、有沒有失敗，不必去翻日誌檔。
- **誰會用到**：負責維運的系統管理員。平常偶爾來看一眼「上次執行」是否都是成功；有作業失敗、或想馬上清一次資料時才需要操作。
- **它在系統的哪個位置**：左側選單「系統管理 › 系統設定與維運 › 排程作業」；各作業清除的資料分別在「稽核紀錄」「系統例外紀錄」「AI 對話紀錄」「Token 用量」查看；「已刪除資料清理」處理的是各管理頁「顯示已刪除」裡的資料。
- **開始前要準備**：知道每種紀錄要保留多久（保留天數在「系統參數」頁調整，預設稽核與 Token 用量 365 天、例外與 AI 對話 90 天、站內通知 90 天（已讀的在標為已讀 7 天後）、已刪除的資料在刪除 90 天後永久刪除）；要調整執行時間，請洽負責部署的人員。
- **做完會得到**：立即執行的結果會出現在「上次執行」與「執行紀錄」；停用的作業不再依排程執行；每一次手動操作都會寫進稽核紀錄。
- **它不做什麼**：不能在這裡修改執行時間（在伺服器設定檔）或保留天數（在「系統參數」頁）；不會還原已經被清除的資料；也不負責日誌檔本身的保留（那是日誌設定檔管的）。

## 一、功能摘要

在這裡可以做什麼：

- 看每個作業的說明、執行時間（cron 寫法）、下次執行時間，以及上次執行的結果、時間、耗時與訊息。
- 按「立即執行」馬上跑一次（在背景進行，完成後頁面自動更新）。
- 用「啟用」開關暫時停用或恢復某個作業的排程。
- 按「執行紀錄」查看該作業最近 50 次的執行經過。
- 立即執行、啟用、停用都會寫進稽核紀錄。

## 二、這個頁面在做什麼

### 誰會使用、為什麼要用

| 角色 | 為什麼要用 |
|---|---|
| 系統管理員（日常巡檢） | 確認每個作業上次都是「成功」，下次執行時間合理。 |
| 系統管理員（處理問題） | 作業顯示「失敗」時，看訊息與錯誤追蹤碼，到「系統例外紀錄」找原因。 |
| 系統管理員（臨時清理） | 磁碟空間吃緊、或剛把保留天數調短時，按「立即執行」馬上清一次。 |

### 作業是怎麼跑的

- 每個作業有自己的執行時間（清理類作業預設每天 03:00、系統備份 02:00、密碼到期提醒 08:00），時間依伺服器的本地時區。
- 網站在該執行的時間沒有開著（例如閒置太久被伺服器停掉）時，下次啟動會**補跑一次**；錯過好幾次也只補一次。
- 同一個作業同一個時段只會跑一次：伺服器重新啟動、或短時間內同時有兩個網站行程，都不會重複執行。
- 作業執行到一半網站被關閉，那一次會記為「中斷」，之後照常在下個時段執行。

### 需要的權限

| 權限 | 可以做的事 |
|---|---|
| 管理員 | 進入這一頁並使用所有功能。只有帳號勾選了「管理員」的人能進來，這個權限**不在**角色管理的權限表裡，無法透過角色開放。 |

### 它跟其他頁面的分工

| 想做的事 | 去哪裡 |
|---|---|
| 確認自動清除有沒有跑、立即清一次、暫停某個作業 | 這一頁 |
| 看被清除的是哪些資料、手動刪除單筆或指定日期之前的紀錄 | 「稽核紀錄」「系統例外紀錄」「AI 對話紀錄」「Token 用量」 |
| 在被自動永久刪除之前還原刪錯的資料 | 專案、分類、團隊、使用者、角色各頁的「顯示已刪除」 |
| 作業失敗時查完整的錯誤內容 | 「系統例外紀錄」（用執行紀錄裡的追蹤碼搜尋） |
| 整體確認系統是否正常，包含排程有沒有逾期 | 「系統健康監控」 |

## 三、畫面上有哪些按鈕、各自做什麼

### 上方工具列

工具列左側寫著「時間依伺服器本地時區；執行時間在 appsettings 的 ScheduledJobSettings 設定。」。

| 按鈕 | 按下後會做什麼 | 右下角會看到的提示 | 注意事項 |
|---|---|---|---|
| 重新整理 | 重新讀取所有作業的狀態。 | 「已更新最新資料」 | 有作業在執行中時，頁面每 5 秒會自動更新，不必一直按。 |

### 表格欄位

| 欄位 | 意思 | 範例 | 怎麼填或怎麼用 |
|---|---|---|---|
| 作業 | 作業名稱與說明（含保留天數在哪裡設定）。 | 稽核紀錄清理 | 唯讀。 |
| 執行時間 | cron 寫法：分 時 日 月 星期。 | `0 3 * * *`（每天 03:00） | 唯讀；要改請洽部署人員修改設定檔。 |
| 下次執行 | 下一次依排程執行的時間。 | 2026-10-05 03:00 | 停用時顯示「已停用」；排程總開關關閉時顯示「排程已關閉」。 |
| 上次執行 | 最近一次的結果、開始時間、耗時與訊息。 | 成功　2026-10-04 03:00:01　0.4 秒 | 結果有：成功、失敗、執行中、中斷、略過；還沒跑過顯示「尚未執行」。 |
| 啟用 | 是否依排程執行。 | 啟用 | 切換後立即生效；停用期間仍可按「立即執行」。 |
| 操作 | 「立即執行」「執行紀錄」。 | — | 固定在表格最右側。 |

### 每列的按鈕

| 按鈕 | 按下後會做什麼 | 右下角會看到的提示 | 注意事項 |
|---|---|---|---|
| 立即執行 | 先跳「立即執行」確認窗：「要立即執行「作業名稱」嗎？執行會在背景進行，完成後這一頁會自動更新結果。」，按「立即執行」後在背景執行一次。 | 「已開始執行「作業名稱」。」 | 同一個作業還在執行時按鈕會變灰；稽核紀錄寫 `Job.Trigger`。手動執行不影響排程時間。 |
| 執行紀錄 | 打開「執行紀錄：作業名稱」窗，列出最近 50 次的開始時間、結果、觸發方式（排程／補跑／手動）、耗時、訊息與追蹤碼。 | 無 | 唯讀；按 Esc 或右上角關閉。執行紀錄預設保留 90 天，天數在「系統參數」頁調整。 |
| 啟用開關 | 切換這個作業是否依排程執行。 | 「已啟用「…」，從下一個時段開始依排程執行。」或「已停用「…」，不會再依排程執行（仍可按「立即執行」）。」 | 重新啟用時不會補跑停用期間錯過的時段；稽核紀錄寫 `Job.Enable`／`Job.Disable`。 |

### 你可能看到的訊息

| 訊息 | 原因與處理 |
|---|---|
| 你沒有權限存取此頁面 | 你的帳號沒有勾選「管理員」，請洽其他管理員。 |
| 這個作業已經在執行中，請等它完成。 | 同一個作業的上一次還沒結束。等「上次執行」變成成功或失敗再試。 |
| 排程總開關已關閉… | 伺服器設定把所有排程暫停了（常見於維護期間），作業不會自動執行，但仍可手動執行。 |
| 排程設定有誤，目前沿用上一份正確的設定… | 有人在網站執行中把設定檔改壞了。排程不會停，但新的設定沒有生效，請洽部署人員依訊息修正。 |
| 執行時發生未預期的錯誤…請以錯誤追蹤碼 … 到「系統例外紀錄」查看詳細內容。 | 作業失敗。到「系統例外紀錄」用那組追蹤碼搜尋，把內容交給開發人員。作業失敗時（0.9.100 起）所有管理員與按「立即執行」的人都會收到鈴鐺通知與一封信。 |
| 永久刪除超過 N 天的已刪除資料：專案 0、分類 0、團隊 0、使用者 0、角色 0。 | 「已刪除資料清理」的結果，列出這次各刪了幾筆；被刪的是哪些可到「稽核紀錄」看 `Project.AutoPurge` 等紀錄。 |
| 刪除 N 則建立超過 90 天的站內通知；刪除 N 則已讀超過 7 天的站內通知。 | 「站內通知清理」的結果：前半是建立超過保留天數的通知（不論已讀未讀），後半是標為已讀超過已讀保留天數的通知；某一項天數設為 0 時，該項不會出現在訊息裡。 |
| 保留天數設為 0，不自動清除。 | 這個清理作業的保留天數被設為 0，所以這次什麼都沒刪；要恢復清除請到「系統參數」頁調整。 |
| 略過 N 筆（期間被還原或變更）。 | 清理途中有人剛好還原了那筆資料，系統留著它不刪。不需處理。 |
| N 個角色仍被使用者當作主要角色，留到下次。 | 有已刪除、但還沒到期的使用者仍以那個角色為主要角色；等那些使用者被清除後，角色會在之後的某一次被刪掉。不需處理。 |
| N 筆受保護（support 帳號或預設角色）不刪。 | 這兩者是系統必要的資料，永遠不會被自動刪除，網站重新啟動時會自動恢復。 |
| N 個附件檔沒刪掉。 | 專案資料已刪除，但附件檔案刪不掉（例如被其他程式開著），留在附件資料夾。不影響系統，可請部署人員手動清理；詳情在日誌。 |
| 同一個作業的另一次執行還沒結束，這次略過。 | 排程時間到了，但上一次（例如手動執行）還在跑，這一次略過；下個時段會照常執行。 |

### 右下角的處理進度提示

作業在背景執行，不會出現持續顯示的處理進度視窗；右下角只會出現短暫的提示（例如「已開始執行」「已更新最新資料」）。執行中的作業在「上次執行」顯示「執行中」，頁面每 5 秒自動更新到結果出來為止。

## 四、建議這樣操作，會得到什麼

### 每週巡檢一次

1. 打開這一頁，看每個作業的「上次執行」是否都是「成功」、時間是否在預期的時段。
2. 看到「失敗」或「中斷」時，按「執行紀錄」看訊息與追蹤碼。
3. 失敗的話到「系統例外紀錄」用追蹤碼搜尋，交給開發人員；處理後按「立即執行」確認恢復。

**會得到什麼**：在資料庫或磁碟被過期資料塞滿之前，就知道自動清除出了問題。

### 剛把保留天數調短，想馬上生效

1. 到「系統參數」頁修改保留天數（例如把例外紀錄從 90 天改成 30 天）。
2. 回到這一頁，在「系統例外紀錄清理」按「立即執行」並確認。
3. 等「上次執行」變成「成功」，訊息會寫刪除了幾筆。

**會得到什麼**：不必等到隔天凌晨，舊資料立刻被清掉，稽核紀錄也會留下 `SystemParameter.Update`、`ExceptionLog.AutoPurge` 與 `Job.Trigger` 三筆紀錄。

### 維護期間暫停某個作業

1. 把該作業的「啟用」關掉。
2. 維護結束後再打開。

**會得到什麼**：停用期間它不會依排程執行；重新啟用後從下一個時段開始執行，不會一口氣補跑停用期間的時段。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **cron** | 描述「什麼時候執行」的寫法，五個欄位依序是分、時、日、月、星期。`0 3 * * *` 是每天 03:00，`30 2 * * 1` 是每週一 02:30。 |
| **補跑** | 網站在該執行的時間沒有開著，下次啟動時發現錯過了，就補執行一次。 |
| **中斷** | 執行到一半網站被關閉或重新啟動，這一次沒做完；下個時段會照常執行。 |
| **略過** | 時間到了但同一個作業的上一次還沒結束，這一次不執行。 |
| **排程總開關** | 伺服器設定檔裡一次暫停所有排程的開關；關閉時仍可手動執行。 |
| **錯誤追蹤碼** | 8 碼的代號，用來在「系統例外紀錄」與日誌中找到同一次執行的錯誤細節。 |

## 七、常見問題

**問：「下次執行」顯示的時間跟我預期的差了 8 小時？**
答：執行時間依伺服器的本地時區計算。若伺服器的時區不是台北時間，時間就會有落差，請洽負責部署的人員確認伺服器時區。

**問：我按了「立即執行」，為什麼還要等？**
答：作業在背景執行，清除的資料多時可能要花一些時間。頁面每 5 秒會自動更新，「上次執行」變成成功或失敗就完成了，期間可以離開這一頁。

**問：作業好幾天都沒有執行（「上次執行」停在很久以前）？**
答：最常見的原因是網站閒置太久被伺服器停掉，排程跟著停了；網站下次啟動時會補跑一次。若經常發生，請部署人員把網站設定為一直執行（應用程式集區「永遠執行」並停用閒置逾時）。

**問：停用作業後資料會不會一直累積？**
答：會。停用期間不會自動清除，資料會依原本的速度增加；請記得在維護結束後重新啟用，或改用「立即執行」手動清一次。

**問：可以在這裡改成每週執行一次嗎？**
答：不行。執行時間在伺服器的設定檔，畫面上只能看、不能改；請洽負責部署的人員修改，修改後一分鐘內生效。保留天數則可以在「系統參數」頁自己調整。

**問：「已刪除資料清理」會刪掉還沒刪除的資料嗎？**
答：不會。它只處理已經被刪除（在「顯示已刪除」裡）、而且刪除時間超過保留天數的資料；平常看得到的資料不受影響。保留天數設為 0 時完全不會自動刪除。

**問：還是解決不了怎麼辦？**
答：請記下發生時間、作業名稱、「執行紀錄」裡的訊息與追蹤碼（最好截圖），以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
