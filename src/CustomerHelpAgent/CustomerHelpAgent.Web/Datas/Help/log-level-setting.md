# 日誌等級設定

決定系統的日誌**要記錄到多細**：排查問題時暫時**調低等級**讓日誌多寫一些細節，查完再**還原為系統預設等級**。調整**立即生效、只在這次執行期間有效**。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：在「日誌檢視」找不到足夠線索時，把日誌暫時調細，讓系統多記下查詢條件、換頁等排錯資訊，重現問題後就能看出原因。
- **誰會用到**：負責排查問題的系統管理員。平常不需要動它，只有在日誌不夠細、看不出原因，或日誌量太大想暫時精簡時才會來。
- **它在系統的哪個位置**：左側選單「系統管理 › 監控與診斷 › 日誌等級設定」；它是「日誌檢視」的上游：這裡決定寫下多少，日誌檢視只能查到已經寫下的內容。
- **開始前要準備**：先想好要重現的操作步驟，並預留排查結束後把等級調回來的時間；調得越細，日誌量增加得越快。
- **做完會得到**：新的等級立即對整個系統生效，之後發生的事件會依新等級寫進日誌檔，稽核紀錄也會留下一筆從哪個等級調到哪個等級的紀錄。
- **它不做什麼**：不會修改任何設定檔，系統重新啟動後就回到預設；不會補回調整之前沒寫下的日誌；也不影響框架本身的日誌。

## 一、功能摘要

在這裡可以做什麼：

- 看「目前生效等級」與「系統預設等級」兩張資訊卡，確認系統此刻記錄到多細、是否被人調整過。
- 從六個等級（TRACE、DEBUG、INFO、WARN、ERROR、FATAL）中選一個，按「套用」立即生效。
- 按「還原為系統預設等級」取消先前的調整。
- 每一次套用與還原都會寫進稽核紀錄，事後查得到是誰、在什麼時候、從哪個等級調到哪個等級。

## 二、這個頁面在做什麼

### 誰會使用、為什麼要用

| 角色 | 為什麼要用 |
|---|---|
| 系統管理員（排查問題） | 日誌不夠細時暫時調到 DEBUG 或 TRACE，重現問題後到「日誌檢視」看細節，查完再還原。 |
| 系統管理員（控制日誌量） | 日誌檔長得太快時暫時調高到 WARN 以上，只記重要的事件。 |
| 系統管理員（接手交班） | 確認前一位管理員有沒有調整過、是否忘了還原。 |

### 等級是怎麼運作的

- 日誌等級是一道「門檻」：只有等級**等於或高於**目前生效等級的事件才會寫進檔案。由細到粗為 TRACE、DEBUG、INFO、WARN、ERROR、FATAL。
- 例如生效等級是 INFO 時，DEBUG 與 TRACE 的訊息會被直接丟棄，日後在「日誌檢視」再怎麼查都查不到。
- 所以正確的順序是：**先調低等級 → 重現問題 → 到日誌檢視查詢 → 回來還原**。

### 調整的影響範圍

- 這個設定對**整個系統**生效，不是只針對你自己；調整期間所有使用者的操作都用新等級記錄。
- 調整只存在這次執行的記憶體裡。系統重新啟動（包括部署新版本、伺服器重開機）後就會回到系統預設等級，不需要手動調回，但也代表調整不會一直保留。
- 套用之後，即使系統重新載入日誌設定檔，這裡的設定仍會保留；要回到設定檔裡的值，請按「還原為系統預設等級」。
- 只影響應用程式日誌；框架日誌（Microsoft、EntityFrameworkCore）另有專屬規則，不受這裡影響。

### 需要的權限

| 權限 | 可以做的事 |
|---|---|
| 管理員 | 進入本頁、套用與還原日誌等級。 |
| 非管理員 | 無法使用。左側選單不會出現這一項；直接輸入網址會看到「你沒有權限存取此頁面」。 |

> 「管理員」是在「使用者管理」裡對使用者勾選的「管理員」，角色管理無法把這一頁開放給一般使用者。

### 它跟其他頁面的分工

| 你想做的事 | 該去哪 |
|---|---|
| 決定日誌要記錄到多細 | 這一頁 |
| 查詢已經寫下的日誌、請 AI 整理 | 「日誌檢視」 |
| 看出過哪幾種錯、各發生幾次 | 「系統例外紀錄」 |
| 快速瞄一眼最近 24 小時的警告與錯誤 | 「系統健康監控」 |
| 查誰在什麼時候調整或還原過等級 | 「稽核紀錄」 |

## 三、畫面上有哪些按鈕、各自做什麼

### 資訊卡

| 欄位 | 意思 | 範例 | 怎麼填或怎麼用 |
|---|---|---|---|
| 目前生效等級 | 系統此刻實際使用的門檻，卡片下方註明「此等級以上的日誌才會寫入檔案」。 | DEBUG | 只能看。套用或還原後會立即更新。 |
| 系統預設等級 | 系統日誌設定檔裡設定的等級，也就是重新啟動後會回到的等級。 | INFO | 只能看。和「目前生效等級」不同，就代表有人在執行期調整過。 |

### 注意事項（黃色區塊）

畫面上的黃色區塊說明了四件事，請務必讀完：

- **這個設定只在執行期有效**。系統重新啟動之後會回到「系統預設等級」，不會寫進任何設定檔。
- 套用之後即使日誌設定檔被重新載入，這個設定仍會保留；要回到檔案裡的值請按「還原為系統預設等級」。
- 本設定**只影響應用程式日誌**；框架日誌（Microsoft、EntityFrameworkCore）另有專屬規則，不受這裡影響。
- **調到 Debug 或 Trace 會大幅增加日誌量**，排查完問題請記得調回來。

### 選擇要輸出的最低等級

打開頁面時，預先選好的就是目前生效等級。由細到粗共六個選項，每個選項後面都有括號說明：

| 欄位 | 意思 | 範例 | 怎麼填或怎麼用 |
|---|---|---|---|
| TRACE | 最詳細，含框架層級細節。 | 追查很難重現的問題 | 會大幅增加日誌量，套用前會先跳確認窗。 |
| DEBUG | 含查詢條件、換頁等排錯資訊。 | 想知道某次查詢實際用了什麼條件 | 會大幅增加日誌量，套用前會先跳確認窗。 |
| INFO | 含使用者操作軌跡，日常建議值。 | 平常運作 | 一般情況建議維持這一級。 |
| WARN | 僅警告以上。 | 日誌檔長得太快，暫時精簡 | 這段期間的一般操作軌跡不會被記下，事後無法補查。 |
| ERROR | 僅錯誤以上。 | 只想留下錯誤 | 同上，記下的內容更少。 |
| FATAL | 僅嚴重錯誤。 | 極少使用 | 幾乎不會留下排錯線索，請謹慎使用。 |

### 按鈕

| 按鈕 | 按下後會做什麼 | 右下角會看到的提示 | 注意事項 |
|---|---|---|---|
| 套用（打勾圖示） | 把選取的等級立即設為生效等級。選 TRACE 或 DEBUG 時，會先跳「確認調整日誌等級」：「調整為 DEBUG 會大幅增加日誌量，請在排查完問題後記得調回來。確定要套用嗎？」，按「套用」才會生效、按「取消」則不變。 | 無（畫面頂端會短暫出現「已套用日誌等級：DEBUG」） | 選取的等級與目前生效等級相同時按鈕停用。調高等級（WARN、ERROR、FATAL）不需要確認。每次套用都會記一筆稽核紀錄 `LogLevel.Apply`。 |
| 還原為系統預設等級（時鐘圖示） | 取消先前的調整，回到系統預設等級。 | 無（畫面頂端會短暫出現「已還原為系統預設等級：INFO」） | 沒有做過調整時按鈕停用。每次還原都會記一筆稽核紀錄 `LogLevel.Restore`。 |

> 圖示按鈕上沒有文字，滑鼠移上去才會顯示按鈕名稱。確認窗點外面不會關閉，請按「套用」或「取消」。

### 你可能看到的訊息

| 訊息 | 原因與處理 |

| 無法讀取 NLog 設定，日誌等級無法在執行期調整。… | 系統讀不到日誌設定，整頁只顯示這段紅色警示，無法調整。請洽負責部署的人員檢查伺服器上的日誌設定檔。 |
| 已套用日誌等級：… | 套用成功，新等級已經生效。 |
| 已還原為系統預設等級：… | 還原成功，已回到系統預設等級。 |
| 套用失敗，請確認 NLog 設定。 | 套用沒有成功，等級維持不變。請洽負責部署的人員。 |
| 還原失敗，請確認 NLog 設定。 | 還原沒有成功，等級維持不變。請洽負責部署的人員。 |

### 右下角的處理進度提示

這個畫面沒有長時間處理的工作，不會出現處理進度視窗；套用與還原的結果以畫面頂端的短暫訊息顯示，幾秒後自動消失。

## 四、建議這樣操作，會得到什麼

### 某個查詢結果不對，想看系統實際用了什麼條件

1. 確認「目前生效等級」是 INFO。
2. 選擇「DEBUG」，按「套用」，在「確認調整日誌等級」視窗再按一次「套用」。
3. 請使用者（或你自己）重做一次那個查詢，並記下操作時間。
4. 到「日誌檢視」查詢那個時間前後、最低等級選「DEBUG」的日誌。
5. 查到需要的資訊後，回到本頁按「還原為系統預設等級」。

**會得到什麼**：那次操作的查詢條件等排錯細節，以及稽核紀錄裡兩筆紀錄（調低與還原），日誌量也回到平常水準。

> 王小明反映「專案項目」用分類「行銷」篩選時結果怪怪的。管理員把等級調到 DEBUG，請他再篩一次，接著在「日誌檢視」查到當時實際送出的查詢條件，確認原因後回到本頁按「還原為系統預設等級」。

### 日誌檔長得太快，想暫時只記重要的事

1. 選擇「WARN」，按「套用」（調高等級不需要確認）。
2. 觀察一段時間，確認日誌量下降。
3. 問題處理完後，按「還原為系統預設等級」。

**會得到什麼**：這段期間只記錄警告以上的事件；但要知道，這段期間的一般操作軌跡不會被記下，事後無法補查。

### 接手時不確定之前有沒有人調過

1. 打開本頁，比對「目前生效等級」與「系統預設等級」。
2. 看「還原為系統預設等級」按鈕能不能按：能按就代表目前是有人手動套用的等級（即使等級剛好和預設相同）。
3. 到「稽核紀錄」查詢動作 `LogLevel.Apply`，確認是誰、何時調整的，再決定是否還原。

**會得到什麼**：確認系統目前是否處於臨時調整狀態，避免細節日誌在沒人注意的情況下持續累積。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **日誌等級** | 每筆日誌的重要程度，由細到粗為 TRACE、DEBUG、INFO、WARN、ERROR、FATAL。 |
| **最低等級** | 門檻值；只有等於或高於這個等級的事件才會寫進日誌檔。 |
| **目前生效等級** | 系統此刻實際使用的門檻值。 |
| **系統預設等級** | 系統日誌設定檔裡的門檻值，重新啟動後會回到這裡。 |
| **執行期** | 系統這一次啟動到下一次重新啟動之間；本頁的調整只在這段期間有效。 |
| **應用程式日誌** | 本系統自己的程式寫出的日誌；框架日誌則是底層套件寫出的，不受本頁影響。 |

## 七、常見問題

**問：我調成 DEBUG 了，為什麼日誌檢視還是查不到昨天的 DEBUG 訊息？**
答：等級只影響「之後」寫下的日誌。調整之前的事件當初就沒有寫進檔案，無法補回。調低等級後必須重現一次問題，才查得到那次的細節。

**問：調低之後忘了調回來，會怎樣？**
答：日誌量會大幅增加，佔用更多磁碟空間。系統重新啟動時會自動回到系統預設等級，但在那之前會一直維持調低的狀態，所以排查完請記得按「還原為系統預設等級」。

**問：選了 TRACE，為什麼還是看不到框架的細節？**
答：本頁只影響應用程式日誌。框架日誌另有專屬規則，由伺服器上的日誌設定檔控制，不受這裡影響；需要時請洽負責部署的人員。

**問：這個調整會影響其他管理員嗎？**
答：會影響同一個系統上的所有使用者，因為日誌等級是整個系統共用的設定。它只存在這一次執行的記憶體中，不會寫進任何設定檔。

**問：「套用」按鈕是灰色的，按不下去？**
答：你選的等級和目前生效等級相同，不需要套用。請先選另一個等級。

**問：還是解決不了怎麼辦？**
答：請記下發生時間、操作的頁面與按鈕、畫面或右下角的訊息（最好截圖；右下角的錯誤訊息可按「複製」，內容、時間與錯誤追蹤碼會一起放進剪貼簿），以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
