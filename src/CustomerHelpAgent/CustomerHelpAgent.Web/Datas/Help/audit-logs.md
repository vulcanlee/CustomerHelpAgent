# 稽核紀錄

查詢系統自動留下的「**誰、何時、從哪個 IP、對什麼、做了什麼、結果如何**」事件紀錄，例如登入成功或失敗、帳號與角色異動、權限被拒絕，以及每個人開了哪些頁、查了什麼、看了哪一筆、改了什麼（0.9.131 起）；並可**匯出查詢結果**或**清除過舊的紀錄**。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：發生帳號被改、角色被動、有人一直登入失敗這類事情時，用來追查是誰在什麼時候、從哪個 IP 做的，結果成功還是失敗。
- **誰會用到**：系統管理員，以及需要做稽核、資安調查的人；一般使用者看不到這一頁。
- **它在系統的哪個位置**：左側選單「系統管理 › 帳號與權限 › 稽核紀錄」；紀錄由登入、使用者管理、角色管理等流程自動寫入，這一頁只負責查看與清理。
- **開始前要準備**：大概知道要查的時間範圍、操作者帳號或事件種類，查起來會快很多；查詢的時間以伺服器所在地的本地時間輸入。
- **做完會得到**：符合條件的事件清單、每一筆的完整明細（含本地時間與國際標準時間），以及可以帶出系統比對的 CSV 檔。
- **它不做什麼**：不能新增、修改或刪除單一筆紀錄；程式錯誤請看「系統例外紀錄」，逐行的系統運作過程請看「日誌檢視」。

## 一、功能摘要

在這裡可以做什麼：

- 依發生時間區間、動作、結果、操作者帳號與關鍵字（含來源 IP）查詢稽核事件。
- 按每列的「查看」打開單筆明細，看完整摘要與國際標準時間（UTC）；修改與查詢的紀錄還能看到「詳細內容」（改了哪些欄位、舊值和新值，或完整的查詢條件；0.9.131 起）。
- 把目前查詢條件下的結果匯出成 CSV，最多 10,000 筆。
- 清除發生在 N 天之前的紀錄（預設 365 天，由系統設定決定），或清空全部紀錄；這兩個動作本身也會再留下一筆紀錄。系統每天也會自動清除一次，並留下一筆 `Audit.AutoPurge`。

頁面上方有一段固定說明：「本頁記錄『誰、何時、對什麼、做了什麼、結果如何』，涵蓋登入、使用者與角色異動、權限拒絕等事件。時間以伺服器本地時區顯示（資料庫存的是 UTC）。清除與清空動作本身也會留下一筆紀錄。」

**修改的前後差異**（0.9.131 起）：分類、專案、團隊、使用者、角色的「修改」（畫面或 Web API），以及使用者在「個人資料」改自己的姓名，都會把「欄位：舊值 → 新值」記在明細窗的「詳細內容」。密碼只記「已變更」、不記內容；額外角色、團隊、角色權限列出新增與移除了哪些。

### 來源 IP

0.9.117 起每筆紀錄都會記下操作者的來源 IP：登入、登出與 Web API 取該次連線的 IP；在畫面上做的操作（例如在「使用者管理」存檔）取的是瀏覽器連上系統時的 IP，網路斷線重連後會更新。系統排程作業自動做的事，以及 0.9.117 之前的舊紀錄，沒有來源 IP，顯示「—」。

### 時間的顯示方式

**資料庫存的是國際標準時間（UTC），畫面上顯示的是伺服器所在地的本地時間**。查詢條件的時間也以本地時間輸入，系統會自動換算。伺服器設在台灣時，本地時間比 UTC 快 8 小時。明細視窗與 CSV 都標明是哪一種時間。

### 摘要記了什麼、沒記什麼

- 使用者異動只記帳號、角色編號與團隊；**在修改窗改「管理員」與「啟用」勾選的變更不會寫進摘要**。在清單點狀態標籤啟用或停用（0.9.120 起）則各自記成 `User.Enable`／`User.Disable`。
- 角色異動只記角色名稱與權限數量，不記勾了哪些權限。
- 登入失敗會記下累計失敗次數；帳號不存在時記「帳號不存在」。
- 寄測試信只記寄送方式與成敗，不記收件者。
- 使用者在右上角鈴鐺刪除自己的通知、按「清除已讀」，不會留下稽核紀錄（只動到自己的通知）。

### 需要的權限

| 權限 | 可以做的事 |
|---|---|
| 管理員（使用者管理裡勾選了「管理員」） | 左側選單看得到這一頁，可以查詢、查看明細、匯出 CSV、清除與清空紀錄。 |
| 其他使用者 | 選單不會出現這一頁；直接輸入網址會看到「你沒有權限存取此頁面」。這一頁無法透過角色管理授權給一般角色。 |

### 它跟其他頁面的分工

| 你想做的事 | 該去哪 |

| 查「誰做了什麼」的操作紀錄 | 這一頁 |
| 查程式錯誤、例外發生幾次 | 「系統例外紀錄」 |
| 看某段時間內系統逐行的運作過程 | 「日誌檢視」 |

## 三、畫面上有哪些按鈕、各自做什麼

### 上方工具列的查詢條件

改了條件之後要按「查詢」才會生效。

| 欄位 | 意思 | 範例 | 怎麼填或怎麼用 |
|---|---|---|---|
| 發生時間（起）～發生時間（迄） | 事件發生的時間區間，以本地時間輸入。 | 2026-09-01 00:00:00～2026-09-26 23:59:59 | 可選到秒，只填一邊也可以；兩端都包含。 |
| 動作 | 只看某一種事件。 | `User.Update` | 預設「動作：不限」。選項只列出資料庫裡**實際出現過**的動作代碼。 |
| 結果 | 只看成功或失敗。 | 失敗 | 預設「結果：不限」，可選「成功」或「失敗」。 |
| 操作者帳號 | 做這件事的人的帳號。 | `user01` | 輸入帳號的一部分即可。 |
| 來源 IP | 事件來自哪個 IP（0.9.123 起）。 | `203.0.113.5`、`192.168.1` | 從開頭比對，輸入完整 IP 或前幾段都可以（`192.168.1` 也會查到 `192.168.10.x`，要精確請輸入完整 IP）。0.9.117 之前沒有記錄 IP 的舊紀錄不會出現。匯出 CSV 也套用這個條件。 |
| 關鍵字（動作／目標／摘要／IP） | 在多個欄位中搜尋。 | `user01`、`192.168.1` | 會比對動作、操作者帳號、目標類型、目標識別、摘要與來源 IP；IP 只輸入前幾段也查得到。 |

### 上方工具列的按鈕

工具列的按鈕是圖示按鈕，滑鼠移上去會顯示名稱。確認窗點視窗外面不會關閉，要按「取消」或確認按鈕。

| 按鈕 | 按下後會做什麼 | 右下角會看到的提示 | 注意事項 |
|---|---|---|---|
| 查詢 | 依條件重新查詢，並回到第 1 頁。 | 無 | 改了條件後要按這個才會生效。 |
| 重新整理 | 重新查詢，並更新「動作」下拉的選項。 | 無 | 剛發生新種類的事件時，按這個讓它出現在選單中。 |
| 匯出目前查詢結果（CSV） | 把目前條件下的**全部**結果（不只這一頁）下載成 CSV。 | 無（瀏覽器直接下載）；失敗時「匯出失敗：…。」 | 查詢結果是 0 筆時按鈕停用。最多 10,000 筆，超過時只匯出排在前面的 10,000 筆。檔名像 `CustomerHelpAgent.Web-audit-20260926-143000.csv`。 |
| 清除 N 天前的紀錄 | N 預設 365，由系統設定決定。先跳確認「清除 N 天前的紀錄」：「將刪除發生時間早於 N 天前的所有稽核紀錄。此動作無法復原，且本次清除會另外留下一筆稽核紀錄。」，按「清除」才執行。 | 「已清除 N 筆紀錄。」；沒有那麼舊的紀錄時「沒有符合條件的紀錄。」 | **無法復原**，請先匯出 CSV 備份（CSV 不含詳細內容）。清除範圍不看上面的查詢條件，被清除紀錄的詳細內容檔一併刪除。完成後會多一筆 `Audit.Purge`。 |
| 清空全部紀錄 | 先跳確認「清空全部稽核紀錄」：「將刪除所有稽核紀錄。此動作無法復原，且本次清空會另外留下一筆稽核紀錄。」，按「清空」才執行。 | 「已清空全部稽核紀錄」 | **無法復原**。完成後清單會剩下一筆 `Audit.ClearAll`，記下是誰清空的。 |

CSV 的欄位依序是：發生時間（本地）、結果、動作、操作者帳號、操作者Id、目標類型、目標識別、摘要、來源IP（0.9.117 起加在最後一欄）。標題特別寫明「本地」，提醒讀檔的人這不是 UTC。

## 四、建議這樣操作，會得到什麼

### 查某個帳號最近是不是一直登入失敗

1. 「操作者帳號」輸入該帳號，「結果」選「失敗」。
2. 按「查詢」，看動作欄是 `Login.Failed`、`Login.LockedOut` 還是 `Login.Disabled`。
3. 按可疑那一列的「查看」，看摘要裡累計失敗了幾次；再看「來源 IP」是不是本人平常用的網路。

**會得到什麼**：這個帳號每一次失敗的時間、原因與來源 IP，可以判斷是本人忘記密碼、帳號被停用，還是有人從陌生的地方在嘗試猜密碼。

### 查某位使用者的角色是誰改的

1. 「動作」選 `User.Update`，「關鍵字」輸入那位使用者的帳號。
2. 按「查詢」，再按可疑那一列的「查看」看完整摘要。

**會得到什麼**：是哪一位管理員、在什麼時間修改了這個人的角色或團隊。

> 業務一組反映 `user01` 突然看不到專案。王小明在「動作」選 `User.Update`、關鍵字輸入 `user01` 後查詢，看到前一天下午有一筆由 `admin` 做的修改，摘要裡的團隊已經不含「業務一組」。他到「使用者管理」把團隊加回去，問題就解決了。

### 年度保存期滿，要清理並留存舊紀錄

1. 「發生時間（迄）」選到一年前，按「查詢」，再按「匯出目前查詢結果（CSV）」下載備份。
2. 按「清除 N 天前的紀錄」（N 預設 365），在確認窗按「清除」。

**會得到什麼**：一份舊紀錄的 CSV 備份，資料表只留最近一年；同時會多出一筆 `Audit.Purge`，記下是誰在何時做了清除。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **稽核紀錄** | 系統自動留下的「誰做了什麼」的事件紀錄，用來事後追查責任。 |
| **動作代碼** | 事件的種類，前半段是類別（例如 `Login`、`User`），後半段是發生了什麼。 |
| **操作者** | 做這件事的人；沒有登入身分的事件顯示「（系統／匿名）」。 |
| **來源 IP** | 做這件事的電腦連上系統時的網路位址，用來判斷是不是從平常的地方操作。 |
| **目標** | 被操作的對象，例如某一位使用者或某一個角色。 |
| **摘要** | 補充說明，例如異動後的角色編號與團隊；只記部分內容。 |
| **UTC** | 國際標準時間。伺服器設在台灣時，本地時間會比它快 8 小時。 |
| **本地時間** | 伺服器所在地的時間，也就是畫面上顯示的時間。 |
| **清除與清空** | 清除只刪 365 天前的紀錄，清空是全部刪除；兩者都無法復原，而且都會再留下一筆紀錄。 |

## 七、常見問題

**問：為什麼畫面上的時間和資料庫裡看到的差了好幾個小時？**
答：資料庫存的是 UTC，畫面顯示的是伺服器本地時間。兩者都正確，只是時區不同；明細視窗會把兩個時間並列。

**問：清空全部紀錄之後，為什麼清單上還剩一筆？**
答：這是刻意的設計。清除與清空完成後，系統會再寫一筆 `Audit.Purge` 或 `Audit.ClearAll`，記下是誰抹除了稽核紀錄，否則這會是整個系統唯一查不到的事。

**問：「動作」下拉裡找不到我要查的事件？**
答：下拉選項只列出資料庫裡實際出現過的動作代碼。那種事件如果從沒發生過，或已經被清除，就不會出現在選單裡；可以按「重新整理」更新選項。

**問：有人帳號打錯而登入失敗，操作者欄為什麼沒有「Id=」？**
答：輸入的帳號在系統裡不存在，所以只記下對方輸入的帳號文字，沒有對應的使用者編號，摘要會寫「帳號不存在」。

**問：我改了某人的「管理員」或「啟用」勾選，為什麼摘要裡看不到？**
答：使用者異動的摘要只記帳號、角色編號與團隊，在修改窗改這兩個勾選不會寫進摘要。你仍然可以從 `User.Update` 看出是誰、在什麼時間改過這個帳號。想讓停用與啟用留下明確的紀錄，請直接點清單上的狀態標籤（0.9.120 起），會記成 `User.Disable`／`User.Enable`。

**問：為什麼有些紀錄的來源 IP 是「—」？**
答：系統排程作業自動做的事（例如每天自動清除舊紀錄）沒有人從瀏覽器操作，所以沒有 IP；0.9.117 之前留下的紀錄當時還沒有記 IP，也會顯示「—」。

**問：還是解決不了怎麼辦？**
答：請記下發生時間、操作的頁面與按鈕、畫面或右下角的訊息（最好截圖；右下角的錯誤訊息可按「複製」，內容、時間與錯誤追蹤碼會一起放進剪貼簿），以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
