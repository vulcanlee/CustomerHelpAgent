# 介面視覺設計規範

- 文件版本：1.8
- 文件狀態：已實作
- 現行系統版本：1.0.0
- 首次實作版本：0.9.30
- 最後核對日期：2026/10/23

## 目的

本文件是「粉梅暖雪」在**常駐介面**（側邊欄、頂欄、卡片、表格、清單頁）的固定設計模式，
以及全站色票的單一來源。浮層（對話窗、確認窗、通知、消息條）另見
[對話窗 UI 設計規範](對話窗%20UI%20設計規範.md)，兩份文件共用同一組色票。

## 1. 分層強度 ⚠️

**浮層果凍，工作區克制。**

| 層 | 視覺 | 為什麼 |
|---|---|---|
| 浮層（Modal／Confirm／Notification／Message）| 完整果凍：毛玻璃、內外亮邊、擠壓回彈 | 出現時間短、是事件，動態與材質有資訊價值 |
| 常駐工作區（表格列、儲存格）| **白／極淡暖白，高對比** | 使用者停留最久、認知負荷最高的地方；整片粉底長時間掃描會累 |
| 常駐外框（側邊欄、頂欄、卡片、按鈕、focus、排序箭頭、分頁）| 粉梅 | 這些是導覽與狀態，染色不影響讀資料 |

⚠️ **不要把表格列底色改成粉色。** 參考來源的比稿頁是「對話窗的背景陪襯」
（該頁自己的說明寫著「用來讓毛玻璃有東西可以透」），只有 4 列 8 欄、沒有排序箭頭、
分頁與固定操作欄。本系統的日誌與 Token 用量頁有 8～10 欄，密度完全不同。

## 2. 樣式寫在哪裡 ⚠️

**判準是 DOM 位置，不是元件名稱，也不是「是不是 `.ant-*`」。**

| 情形 | 位置 |
|---|---|
| 色票 token、形狀、動態 easing | `wwwroot/theme.css` 的 `:root` |
| AntDesign 渲染在 **`AntContainer` 底下**（Modal／Confirm／Notification／Message）| `Components/Commons/OverlayStyles.razor` |
| AntDesign 渲染在 **頁面 DOM 內**（Table／Pagination／Input／Select／DatePicker／Tag）| `wwwroot/theme.css` |
| 元件或檢視自己寫的 markup | 各自的 `.razor.css`，顏色一律 `var(--app-*)` |

背後的機制：

- 浮層被 AntDesign portal 到 `AntContainer` 底下，**脫離了檢視的 DOM 子樹**，
  所以 scoped CSS 與 `::deep` 都打不到（`::deep` 編成 `[b-hash] 後代`，而外框不在那個子樹裡）。
- 表格與側邊選單**渲染在元件自己的子樹內**，`::deep .ant-menu-*` 之類其實有效
  —— `NavMenu.razor.css` 就是這樣寫的。⚠️ **但這正是陷阱**：在某個檢視的 `.razor.css` 裡寫
  `::deep .ant-table-*` 會生效，於是被複製到另外九個檢視去。表格要的是全站一致，所以走全域。
- `:root` 只能寫在**真正的 `.css`**。scoped CSS 會被改寫成 `:root[b-xxxxxxxxxx]`，
  永遠匹配不到任何東西 —— 這就是本專案在 0.9.30 之前一個 `:root` 都沒有的原因。
  scoped 檔案要宣告變數時掛在最外層容器 class 上。

### 2.1 載入順序 ⚠️

`Components/App.razor` 的 `<link>` 順序：

```
bootstrap → app.css → CustomerHelpAgent.Web.styles.css → …
→ _content/AntDesign/css/ant-design-blazor.css → theme.css → Google Fonts
```

**`theme.css` 必須排在 AntDesign 之後。** 排在前面的話，同分特異性會輸給後載入的 AntDesign，
所有清單頁的表格／分頁／輸入框樣式會**同時**退回預設 —— 而且建置、`dotnet format`、
`TreatWarningsAsErrors` 三道關卡**全都看不到**。由
`CustomerHelpAgent.Tests/ThemeConventionTests.ThemeCss_ShouldLoadAfterAntDesignStylesheet` 守門。

即使排在後面，`theme.css` 內對 `.ant-*` 的規則仍一律加 `!important`：
全專案的 `.ant-*` 覆寫都這樣寫（速查表 §6.4），維持單一心智模型，
也免疫於個別選擇器的特異性誤判。

⚠️ `theme.css` 是真正的 `.css`，at 規則寫**一個** `@`。從 `OverlayStyles.razor`
複製規則過來時要把 `@@media` 改回 `@media` —— `@@media` 是無效的 at 規則，
會讓**整個區塊**靜默失效，主控台不會有任何訊息。反方向複製則要記得加回去。

- 破壞性動作：刪除鈕、登出項、確認窗的紅調。
- Token 用量的「未定價」琥珀 `#d46b08`。

## 4. 表格 ⚠️

全站 21 張 `<Table>`（分布在 20 個元件，0.9.135）共用 `theme.css` 裡的一份規則，各檢視的 `.razor.css` **不需要也不應該**
重寫。各檢視既有的 `.<前綴>-toolbar` / `-table-wrap` 只有 flex 版型，沒有顏色。

| 元素 | 規格 |
|---|---|
| 表頭 | `--app-thead` 底、`--app-text` 字、下框 `--app-line`、拿掉欄間直線 |
| 列 | 奇數 `--app-row`、偶數 `--app-row-alt`、hover／選取 `--app-row-hover` |
| 排序箭頭 | 未啟用 `--app-accent-dim`、啟用 `--app-accent` |
| 分頁目前頁 | `--app-tint` 底、`--app-accent` 邊框與文字、膠囊圓角 |
| 分頁籤（Tabs）| 作用中與 hover 的文字、底線 `--app-accent`（0.9.108 起；之前是 AntDesign 藍） |
| 輸入框聚焦 | `--app-accent-dim` 邊框 ＋ `0 0 0 5px var(--app-accent-soft)` 柔光 |

### 4.1 兩個一定會踩的陷阱

⚠️ **列的底色一律寫在 `> td` 上，不可寫在 `tr` 上。**
固定欄（`.ant-table-cell-fix-left` / `-fix-right`）自帶 AntDesign 給的**不透明白底**
（它必須蓋住捲到底下的內容）。規則寫在 `tr` 上打不到它，
十四個有 `<ActionColumn Fixed>` 的頁面（使用者、角色、分類、專案、團隊等）
滑過整列時會看到「操作」欄留下一塊白。
同理，`--app-row*` 三個值**不可改成 rgba** —— 半透明會讓固定欄透出殘影。

⚠️ **排序中的欄位要一起覆寫。** AntDesign 另外用 `td.ant-table-column-sort` 把該欄染灰，
而每一張表都有 `DefaultSortOrder`，所以**永遠有一欄**吃到它。漏掉的症狀是
「整列變暖，只有那一欄還是灰的」。三種狀態（一般／斑馬／hover）都要寫。

## 5. 側邊欄

深梅漸層底、淺色字，是全站唯一的深色面。

| 元素 | 規格 |
|---|---|
| 底 | `--app-rail` |
| 一般項 | `--app-rail-text`，圖示 `--app-rail-icon` |
| **葉節點的 `<a>`** ⚠️ | `--app-rail-text-sub`（比群組標題淡一階做層次）|
| 選取指示條（右緣 3px）| `--app-accent-light` |
| hover | `--app-rail-hover`（白色 10%），保留 `translateX(2px)` |
| 選取項 | `--app-rail-active`，文字 `--app-on-accent` |
| 次要文字（副標、分組標題）| `--app-rail-faint` |
| 焦點環 | `--app-rail-ring`（**實色淺環**）|
| 收合飛出面板 | **維持淺粉**：`--app-tint` 底、`--app-line` 邊、`--app-text` 字 |

飛出面板不跟著變深，是因為它浮在**白色內容區**上，深梅面板會像一塊斷裂的方塊；
而且依 §1 的分層，浮在內容之上的東西屬於浮層那一層。

⚠️ **葉節點的顏色必須另外打在 `<a>` 上，打在 `<li>` 上沒有用**（0.9.40 起）。
AntDesign 的 `MenuItem` 只要有 `RouterLink`，就會在 `<li class="ant-menu-item">` 裡面
**再包一層 `<a>`**，而它出廠自帶 `.ant-menu-item a { color: rgba(0,0,0,.85) }` 與
`.ant-menu-item-selected a { color: #1890ff }`。CSS 的 `color` 在子元素被直接指定時不會繼承，
所以只打在 `<li>` 上的規則到不了文字 —— 深梅底上會變成**黑字與藍字**。

這個缺陷難以察覺的地方在於「看起來大部分都對」：群組標題是 `<div>`、「登出」走 `OnClick`，
兩者都沒有那層 `<a>`，所以一直是白的；圖示用的是後代選擇器，本來就穿得過 `<a>`。
由 `SidebarLinkColorConventionTests` 守門。

### 5.1 對比 ⚠️

- 白字對 `#4a1028` 約 15:1、對 `#6b1c3d` 約 11:1 —— 安全。
- 白字對 `#a52b59` 約 5.6:1 —— 通過 AA。
- **白字對 `#c43970` 只有約 4.2:1，未達 AA。** 因此 `--app-rail-active` 的亮端封頂在 `#a52b59`。
  ⚠️ **不要把 active 區塊改用 `--app-primary-grad`** —— 它的亮端 `#ea88ad` 對白只有約 2:1。
- 0.9.40 的實算值（底色取漸層最亮端 `#6b1c3d`，最不利情況）：
  群組標題 `--app-rail-text` **8.58:1**、葉節點 `--app-rail-text-sub` **7.09:1**、
  hover `--app-rail-text-strong` **10.73:1**、選取項白字對 `#a52b59` **6.45:1**、
  副標 `--app-rail-faint` **4.86:1**（通過但最接近下限，不要再調淡）。
- 修正前的失效值：葉節點黑字 **1.78:1**、選中藍字對莓紅 **2.09:1** —— 兩者都遠低於 AA。
  ⚠️ 至於右緣那條藍色指示條，實算是 **3.48:1**，**有**通過非文字元素的 3:1 門檻；
  換成 `--app-accent-light`（6.76:1）是**配色一致性**的決定，不要把它說成無障礙修正。
- 深色面上的焦點環必須是**實色淺環**。原本的半透明藍環在深梅底上等於看不見，
  那是真正的無障礙退化，而且不會有任何徵兆。

## 6. 狀態徽章

`Components/Commons/StatusPill.razor`，參數 `Text`、`Tone`，以及 0.9.120 起的 `OnClick`、`Hint`。

| Tone | 用途 |
|---|---|
| `Positive` | 啟用、已完成（綠） |
| `Muted` | 停用、未開始（灰） |
| `Warning` | 暫緩、需注意（琥珀） |
| `Accent` | 進行中、管理員（粉梅） |
| `Neutral` | 其餘 |

⚠️ **語氣對應寫在呼叫端，不要寫進元件。**「等待」在專案是中性，在別的模組可能是警示，
元件無從得知。範例見 `ProjectViewView.razor.cs` 的 `ResolveStatusTone`。

### 6.1 可點的狀態標籤（0.9.120 起）

分類、團隊、使用者清單上點「啟用／停用」標籤就直接切換（停用先確認、啟用直接切換，見對話窗規範 §9.3）。

| 參數 | 行為 |
|---|---|
| `OnClick` | 有給（`HasDelegate`）才渲染成 `<button type="button" class="status-pill … status-pill-clickable">`；沒給維持原本的 `<span>`。處理期間按鈕 `disabled`，連點不會送出兩次 |
| `Hint` | 滑鼠提示（`title`），例如「點一下切換為停用」；`aria-label` 組成「文字：提示」 |

- 可點樣式在 `StatusPill.razor.css` 的 `.status-pill-clickable`：button 預設外觀歸零、手指游標，hover 邊框轉 `currentColor`，
  鍵盤焦點 `2px solid var(--app-accent)` 外框，處理中游標 `progress`。語氣色不變。
- **只有有權限時才可點**：分類、團隊以 `<RequirePermission Page Action="@PermissionActions.Edit">` 包可點的那一份，
  `Fallback`（0.9.120 起）放不帶 `OnClick` 的同一個標籤；使用者清單改看 `MyUserService.CanToggleStatus`（support 與自己不可停用）。
  「顯示已刪除」時一律不可點。
- 切換呼叫只改那一欄的 `SetEnabledAsync`／`SetStatusAsync`，不可拿清單列呼叫整筆覆寫的 `UpdateAsync`（速查表 §6.27）。

沿革：0.9.30 之前分類清單與團隊清單各帶一份**逐字相同**的 `.category-status` /
`.team-status`（連色碼都一樣），使用者管理與專案項目則是純文字 —— 同一個概念三種長相。

## 7. 動態

| 元素 | 效果 |
|---|---|
| 表格列 hover | 200ms 背景過渡（沿用 AntDesign 既有的 transition，不要再疊一層） |
| 工具列按鈕 | hover 上移 1px、按下 `scale(0.97)`，`--app-ease-jelly` 220ms |
| 分頁、排序箭頭 | 顏色過渡 |

⚠️ **清單頁不加進場動畫。** 不只是「每次導覽都重播會煩」—— AntDesign 在每次
`OnChange`（排序、換頁、搜尋）都會重繪 `tbody`，掛在列上的進場動畫會在**每次點欄位標題時**
整張表重新綻放一次。那不是品味問題，是缺陷。

原則：**浮層是事件**（使用者造成、疊在既有內容上，進場動畫有資訊價值）；
**清單頁是目的地**（進場動畫純粹是成本）。

⚠️ 所有位移與縮放都要有 `@media (prefers-reduced-motion: reduce)` 降級，顏色回饋保留。

看起來像外來物的是外框，不是號誌。0.9.31 把兩者分開：

⚠️ **那三組語意色刻意不收進 `theme.css`。** 它們是本頁的語意常數，不是品牌色票 ——
收進去會讓「換品牌色」連帶改掉紅綠燈。`ThemeConventionTests` 的色票清單不含它們，
所以不會誤報；看到它們寫死在 `.razor.css` 裡**不是漏掉**。

⚠️ **狀態色條用 `box-shadow: inset 6px 0 0 0 <色>`，不要改回 `border-left: 6px`。**
6px 的左邊框與 1px 的上下邊框在圓角轉角處會接成一塊楔形；inset 陰影則順著圓角裁切。

⚠️ 摘要卡的 `<h1>` 是**視覺隱藏**不是刪除（`.summary-main h1`）。頂部列已經顯示同一句
標題，但那是 `MainLayout` 的一個 `div`，補不了文件標題層級的洞。手法與
`CrudActionButton` 的 `.crud-action-button-label` 一致。

⚠️ `.health-item` 用的是 `<article>` 元素，而 `MainLayout.razor.css` 有一條 `article` 規則。
**兩者打不到彼此** —— scoped CSS 的 scope 屬性依元件而異。不要為此改元素名稱或加選擇器。

已知的既有死 CSS（回報，未處理）：`EmptyLayout.razor.css` 與 `NoFooterLayout.razor.css`
裡的 `.sidebar` / `.top-row` 規則 —— 這兩個 layout 都沒有渲染那些元素。

## 9. 守門測試

`src/CustomerHelpAgent/CustomerHelpAgent.Tests/ThemeConventionTests.cs`：

1. `ThemeCss_ShouldLoadAfterAntDesignStylesheet` —— 載入順序（§2.1）。
2. `PaletteHexes_ShouldOnlyLiveInThemeCss` —— 色票不得分叉（§3）。
3. `PaletteHexes_ShouldStillExistInThemeCss` —— **清單自己不得過期**（0.9.34 起）。

`src/CustomerHelpAgent/CustomerHelpAgent.Tests/SidebarLinkColorConventionTests.cs`（0.9.40 起）：

4. `SidebarMenuAnchors_ShouldHaveExplicitColorOverrides` —— 側邊欄葉節點的 `<a>`
   必須有顏色覆寫（§5 的那條 ⚠️）。
5. `SidebarMenuAnchorOverrides_ShouldUseImportant` —— 覆寫必須帶 `!important`，
   因為 scoped CSS 束在 `App.razor` 裡排在 AntDesign **之前**。

這五條擋的都是「不會壞、建置不會紅、測試全綠，只有開頁面才看得出來」的漂移。
（可點狀態標籤的行為另由 `CustomerHelpAgent.Tests/Components/` 的 `StatusPillTests` 與 `RequirePermissionTests`（bUnit）守住。）

### 9.1 為什麼需要第 3 條 ⚠️

第 2 條只會在**別的檔案**找到清單上的色碼時失敗。一旦整組品牌色被換掉
（例如粉梅改成綠色系），舊色碼在任何地方都找不到了 —— 那條檢查會**靜默通過**：
還是綠燈，但守的是一組已經不存在的顏色，實際上不再保護任何東西。

這是 0.9.34 實際換一次綠色系驗證出來的 —— 全站換完，測試照樣全綠。

第 3 條要求清單裡的每個色碼都必須真的還在 `theme.css` 裡（註解不算），
換色時就會紅燈提醒你同步清單。作法與 `FormModalConventionTests` 的待遷移清單、
品質關卡（`scripts/Invoke-QualityGate.ps1`）弱點掃描的允許清單相同 —— **清單不可以放著爛掉**。

> 兩條檢查都用同一個 `StripBlockComments` 把 `/* … */` 整段挖空再掃。
> 不能只判斷行首是不是 `/*` 或 `*`：本專案的註解大量橫跨多行且續行不對齊，
> 那樣寫會讓續行裡的色碼被當成程式碼（誤報）或被當成宣告（漏報）。

換品牌色的完整步驟見 [腳手架開發指引 §8.1](../guides/腳手架開發指引.md)。
