# 密碼種類與儲存機制

- 文件版本：1.9
- 文件狀態：已實作
- 現行系統版本：1.0.0
- 首次實作版本：0.2.6
- 最後核對日期：2026/10/23

## 目的

本文件彙整腳手架專案中所有與「密碼」相關的種類、儲存位置與處理方式，釐清哪些是真正逐筆儲存於資料庫的密碼、哪些是設定檔中的密碼或常數，以及哪些屬於機密金鑰（嚴格說不是帳號密碼）。

## 總覽

### 真正的「密碼」

| 種類 | 儲存位置 / 欄位 | 形式 |
| --- | --- | --- |
| 使用者帳號密碼 | 資料庫 `MyUser.Password`（`MyUser.Salt` 僅供舊資料相容） | PBKDF2-SHA256 雜湊（自描述字串，鹽內含）；登入時自動升級舊 SHA256 |
| 啟動種子管理員密碼 | 設定檔 `BootstrapSettings:SupportPassword` | 明碼（範本出貨 `support`） |
| 舊的「需變更密碼」常數 | 程式常數 `MagicObjectHelper.NeedChangePassword` | 明碼常數（`123456`）。0.9.101 起不再代表狀態，只在登入時用來替還在用它的舊帳號補上 `MustChangePassword` 旗標 |
| 密碼歷史（0.9.101 起）| 資料庫 `PasswordHistory.PasswordHash` | 與 `MyUser.Password` 相同的 PBKDF2 雜湊字串；只保留最近 `PasswordPolicySettings:HistoryCount` 筆，供「不可重複」檢查 |
| 忘記密碼的重設 token（0.9.60 起）| 資料庫 `PasswordResetToken.TokenHash` | 只存 SHA-256（十六進位）；原始值只出現在寄出的信中連結。30 分鐘效期、單次使用。嚴格說不是密碼，但拿到原值等於能改密碼 |

### 機密金鑰（非帳號密碼，但常被歸類為「密碼」）

| 種類 | 儲存位置 |
| --- | --- |
| JWT 簽章金鑰 `JwtSettings:SigningKey` | `appsettings.json`（建議以 user-secrets / 環境變數覆寫） |
| Google OAuth 用戶端密鑰 `GoogleOAuthSettings:ClientSecret` | `appsettings.json`（支援 user-secrets / 環境變數） |
| SMTP 登入密碼 `EmailSettings:Password`（0.9.59 起）| `appsettings.json` 出貨空字串；實際值走 user-secrets / 環境變數 `EmailSettings__Password`，不進版控、不寫日誌 |
| AI 服務金鑰 `AiSettings:ApiKey` | `appsettings.json` 出貨空字串；實際值建議走 user-secrets / 環境變數 |

## 1. 使用者帳號密碼（核心）

整個系統中，唯一以資料表欄位形式逐筆儲存的密碼就是 `MyUser.Password`，搭配 `MyUser.Salt`。

- 資料表欄位：`src/CustomerHelpAgent/CustomerHelpAgent.AccessDatas/Models/MyUser.cs`
  - `Password`：PBKDF2 雜湊後的自描述字串，不存明碼。
  - `Salt`：僅供**舊 SHA256 資料相容**；PBKDF2 新格式的鹽已內含於 `Password` 字串中，不再需要此欄位。
- 記憶體傳輸用鏡像：`MyUserAdapterModel.Password` / `.Salt`（`src/CustomerHelpAgent/CustomerHelpAgent.Models/AdapterModel/MyUserAdapterModel.cs`），僅在傳輸/編輯時暫存，不落地保存。

### 雜湊機制（PBKDF2 + 舊格式自動升級）

密碼雜湊由 `SecurePasswordHasher`（`src/CustomerHelpAgent/CustomerHelpAgent.Business/Helpers/SecurePasswordHasher.cs`）產生與驗證：

- **產生**：`SecurePasswordHasher.HashPassword(password)` 以 PBKDF2-SHA256（隨機鹽、10 萬次迭代）產生自描述字串：

  ```
  PBKDF2.SHA256$<迭代次數>$<鹽Base64>$<雜湊Base64>
  ```

- **驗證**：`SecurePasswordHasher.VerifyPassword(password, storedPassword, legacySalt)` 回傳 `PasswordVerificationOutcome`：
  - `Success`：新格式驗證成功。
  - `SuccessRehashNeeded`：偵測到舊 SHA256 格式且比對正確——呼叫端應觸發升級。
  - `Failed`：驗證失敗。
- **自動升級**：使用者以舊 SHA256 密碼登入成功時，`MyUserServiceLogin` 會即時以 PBKDF2 重新雜湊並寫回 `MyUser.Password`（見第 3 節）。無需資料庫遷移，舊帳號逐次登入後自然汰換。

> 相容說明：舊格式驗證仍透過 `PasswordHelper.GetPasswordSHA(salt, password)` 計算比對（保留供升級判斷）。`PasswordHelper.GetGodPasswordSHA` 與 `GodSalt版本` 為無呼叫點的 dead code，保留供未來判斷。

### 密碼的三種來源，皆收斂到同一欄位

`MyUser.Password` 同時涵蓋以下三種情境，最後都以雜湊形式寫入同一欄位：

1. **一般本地帳號登入密碼** — 管理者於使用者管理建立 / 變更密碼、或本人在 `/ChangePassword` 變更時寫入。
2. **啟動種子管理員密碼** — `support` 帳號於系統啟動時種子建立（見第 4 節）。
3. **忘記密碼重設**（0.9.60 起）— 使用者以信中連結於 `/Auths/ResetPassword` 設定，由 `PasswordResetService.ResetAsync` 以 PBKDF2 雜湊寫入，並解除帳號鎖定。只適用於**已有本地密碼**的帳號（沒有本地密碼的 Google 帳號與 `support` 被排除）。

0.9.101 起 1 與 3 一律經 `IPasswordPolicy`：先檢查規則（`PasswordPolicySettings`，預設至少 8 字、要有英文與數字）與歷史（不可與最近 3 次相同，含目前的），
再由 `ApplyAsync` 雜湊寫入，同時記下 `MyUser.PasswordChangedAtUtc`、設定 `MustChangePassword`、更換 `MyUser.SecurityStamp`（其他裝置的登入與 refresh 一併失效，0.9.103 起）、解除鎖定並寫 `PasswordHistory`。
`SecurePasswordHasher.HashPassword` 只准出現在 `PasswordPolicy`、support 種子與登入時的舊雜湊升級（`PasswordPolicyTests` 守門）。

## 2. Google 使用者（不支援 API）

0.9.63 起移除「設定 API 密碼」（`/Profile`）與 `MyUserService.SetOwnApiPasswordAsync`（0.9.102 起同一個網址是個人資料頁，不能設密碼）。Google 帳號只用於網頁登入，
預設沒有本地密碼，**不支援**以 `/api/v1/auth/login` 取得 JWT；要呼叫 API 請使用本地帳號。
0.9.63 之前已自行設過密碼的 Google 帳號，那組雜湊仍留在 `MyUser.Password`，系統不主動清除。

## 3. 登入與 JWT 驗證

無論是 UI 帳號密碼登入或 API 換取 JWT，皆比對 `MyUser.Password`：

- 比對邏輯：`MyUserServiceLogin.LoginAsync(username, password)`（`src/CustomerHelpAgent/CustomerHelpAgent.Business/Services/Other/MyUserServiceLogin.cs`）。
- 以 `SecurePasswordHasher.VerifyPassword` 比對；`Failed` 以外皆視為通過。若回傳 `SuccessRehashNeeded`（舊格式），登入成功後會即時將密碼升級為 PBKDF2 寫回資料庫（升級失敗不影響登入）。

## 4. 啟動種子管理員密碼（SupportPassword）

- 設定欄位：`appsettings.json` 的 `BootstrapSettings:SupportPassword`（範本出貨 `support`），對應類別 `SystemSettings.cs` 的 `BootstrapSettings.SupportPassword`。
- 用途：系統啟動時種子建立 `support` 管理帳號，由 `SupportUserSeeder`（`src/CustomerHelpAgent/CustomerHelpAgent.Business/Startup/SupportUserSeeder.cs`，0.9.91 起；之前寫在 `Program.cs`）取得此設定值後，以 `SecurePasswordHasher.HashPassword` 雜湊後寫入 `MyUser.Password`；既存帳號僅在現有雜湊未通過驗證時才重設（避免每次啟動改寫，並順帶升級舊格式；重設時一併更換 `SecurityStamp`，0.9.103 起）。
- 安全防護：`StartupSafetyValidator` 會在 Production 環境阻擋**留空**，以及範本出貨的預設值（`support`），避免正式環境沿用弱密碼或把管理員設成空密碼。判準由 `StartupSafetyConventionTests` 讀 `appsettings.json` 實際出貨的值守門。

## 5. 「必須變更密碼」（0.9.101 起改用旗標）

- 狀態欄位：`MyUser.MustChangePassword`（管理員新增使用者或替使用者設定密碼時預設勾選）與 `MyUser.PasswordChangedAtUtc`（`PasswordPolicySettings:ExpiryDays` > 0 時用來判斷到期）。
- `AuthenticationStateHelper.Check` 每次換頁以 `IPasswordPolicy.RequiresChange` 判斷，成立就導向 `/ChangePassword`；support 帳號與沒有本機密碼的帳號豁免。
- 0.9.100 之前以「密碼等於 `MagicObjectHelper.NeedChangePassword`（`123456`）」表達這個狀態，每次換頁都要算一次 PBKDF2。舊資料只有雜湊、無法用 SQL 轉換，
  所以登入成功時若明文是 `123456` 就補上旗標；常數只剩這個用途。

## 6. 機密金鑰（非帳號密碼）

以下屬於系統機密，與帳號密碼性質不同，存於設定檔而非資料表：

- `JwtSettings:SigningKey`：JWT 簽章金鑰，正式環境務必以 user-secrets 或環境變數覆寫，勿沿用範本預設值。
- `GoogleOAuthSettings:ClientSecret`：Google OAuth 用戶端密鑰，支援 user-secrets / 環境變數。
- `EmailSettings:Password`、`AiSettings:ApiKey`：SMTP 密碼與 AI 服務金鑰，出貨皆為空字串，見上方總覽表。

## 結論

實際以資料表欄位逐筆儲存的密碼只有一個 —— `MyUser.Password`，新建/變更一律為 PBKDF2-SHA256 雜湊，舊 SHA256 資料於登入時自動升級（`Salt` 僅供舊資料相容）。一般登入、種子管理員、忘記密碼重設三者皆收斂到此欄位；`PasswordHistory` 只保存最近幾組的雜湊供比對；`SupportPassword` 是來源、`NeedChangePassword` 是舊資料相容用的常數，而 `SigningKey`、`ClientSecret` 則屬於機密金鑰。
