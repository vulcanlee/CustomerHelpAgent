## 改名待辦
- [ ] 複刻前先把腳手架更新到最新：`git switch main`、`git pull`，工作目錄沒有未提交的修改（0.9.116 起腳本會檢查，不符合就中止），並記下腳手架的 `SystemVersion`（複刻後會重設為 `1.0.0`）。
- [x] 可使用 `scripts/New-StarterProject.ps1 -ProjectName 新系統代號 -DestinationPath 目標目錄` 產生新專案副本。前置條件：已安裝 `dotnet-ef`（`dotnet tool install --global dotnet-ef`），腳本一開始就會檢查。腳本的行為依版本累加：
  - 0.9.1 起：保留 `docs/*.md` 的 BOM、在 csproj 產生新的 `UserSecretsId`、確實排除 `bin`/`obj`/`.vs`。
  - 0.9.46 起：預設清掉腳手架自己的開發史（`-KeepStarterHistory` 可保留）。
  - 0.9.47 起：文件內引用到舊 `UserSecretsId` 的路徑範例也一併換掉。
  - 0.9.57 起：清空 Migrations，以 `dotnet ef migrations add Init` 重建新專案的第一次 migration。
  - 0.9.65 起：替 `launchSettings.json` 產生一組新的開發連接埠。
  - 0.9.71 起：`SystemVersion` 重設為 `1.0.0 (執行當天)`，文件頭的「現行系統版本」一併改為 `1.0.0`。
  - 0.9.87 起：舊埠改從來源的 `launchSettings.json` 讀取（從衍生專案再衍生也會換埠）、排除 `artifacts`／`.gstack`／`PublishProfiles`／`.claude\settings.local.json` 等本機產物並刪掉空資料夾、全小寫的 `customerhelpagent` 也會替換、`-ProjectName` 每段都必須是合法的 C# 識別字。
  - 0.9.116 起：開跑前確認腳手架來源是最新的（先 `git fetch origin`；工作目錄乾淨、在 origin 的預設分支、不落後 origin），否則中止，`-AllowUnsyncedSource` 可放行；不是 git repo、沒有 origin 或 fetch 失敗只警告；被 `.gitignore` 忽略卻會被複製的檔案會列出警告。寫死腳手架舊 migration 名稱的 `CategoryTeamUniqueIndexMigrationTests.cs`、`TeamTreeMigrationTests.cs` 在複刻時刪除。
  - 0.9.136 起：`crud-templates` 的 `.tmpl` 樣板也替換專案名稱。
  - 0.9.137 起：`.gitignore`、`.props` 也替換專案名稱（`.gitignore` 對 `Backup/` 程式碼的例外規則帶專案名，沒換的話衍生專案的 `Backup/*.cs` 提交不進 git）。

  **整個方案只要執行這支腳本一次**，`.slnx` 內的 7 個專案、方案檔與外層 `src/CustomerHelpAgent/` 目錄會一起改名，不需要為了七個專案跑七次。
